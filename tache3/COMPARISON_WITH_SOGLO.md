## Détail des sept types

| `rafi` | Soglo | Relation |
|---|---|
| XXE, déclaration DOCTYPE et entités externes explicitement permises | XXE, paramètres sûrs absents | Même famille, constructions différentes. |
| Traversée de chemin par `root.resolve(name)` puis lecture | SHA-1 dans `DigestHelper.sha1Demo` | Différents. |
| `Runtime.exec(command)` | `new ProcessBuilder(command)` sans `start()` | Même famille de contrôle de commande, effet immédiat différent. |
| Concaténation SQL dans `executeQuery` | SQL via `String.format` puis `executeQuery` | Même famille, construction différente. |
| `ObjectInputStream.readObject()` non filtré | `ObjectInputStream.readObject()` non filtré | Très semblables. |
| `AES/ECB/PKCS5Padding` | `Math.random()` pour un jeton | Différents risques cryptographiques. |
| Configuration lue via HTTP | Socket TCP non chiffrée | Même famille de transport en clair, API différente. |

Une alerte Semgrep est une correspondance statique, pas une preuve d'exploitabilité. Dans `rafi`, les sept règles locales ont été écrites pour des formes de code précises; leur taux de détection sur ces exemples ne mesure pas la capacité de trouver toutes les variantes. Dans la branche de Soglo, le `ProcessBuilder` non démarré réduit la force de l'exemple d'exécution de commande. Les deux ensembles de méthodes sont inutilisés par le fonctionnement normal de Tika : c'est le principal risque de réalisme pour la rubrique « modifier le code ».

## Estimation et verdict

| Rickroll (10) | 9 | 9 |
| **Total estimé /100** | **84** | **86** |

**Les deux implémentations accomplissent essentiellement le même devoir**, avec des exemples seulement partiellement semblables. Le contrôle Semgrep de Soglo est **meilleur pour l'intégration au workflow existant, la couverture de tout le dépôt et l'usage de règles publiques**. Celui de `rafi` est **meilleur pour la preuve reproductible, l'artefact JSON et les pushs sur la branche de travail**. Soglo a réalisé l'intégration au build complet et aux tests E2E que `rafi` n'a pas; `rafi` a publié les rapports bruts et une comparaison plus précise que Soglo n'a pas. Les deux détectent un test échoué avant le Rickroll; Soglo couvre davantage de suites.

**Si je devais choisir une seule branche pour maximiser la note selon la formulation exacte du barème, je choisirais celle de Soglo**, qui modifie le workflow existant et scanne tout Tika, malgré son run Linux rouge à cause de MinIO. Une version combinée serait plus forte : conserver son intégration et ses règles publiques, ajouter les rapports JSON avant/après et l'artefact différentiel de `rafi`, puis résoudre ou isoler le problème externe MinIO sans affaiblir les tests. Cette recommandation est analytique; aucune fusion ni modification de sa branche ou de la soumission officielle n'a été effectuée.
